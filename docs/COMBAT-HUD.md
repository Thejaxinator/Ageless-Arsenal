# Combat HUD placement

The ammunition card and ability row use the theme selected in HUD Settings (default key **O**). The same style and scale apply immediately to both. An equipped ability remains visible with an empty hand, a tool or a vanilla weapon. Four completely unassigned active slots leave the row hidden. The Ability HUD switch hides the row independently of the ammunition card. F1, spectator mode, and an open screen hide the in-world display.

The original NeoForge post-hotbar callback calls `DestinyHudRenderer.renderWeaponTelemetryHud`. Its new body delegates to `BinderHud.render`, which draws both pieces. The ammo card has a ten-pixel left inset. Four themes center the ability row below it. Simple Minimal and Borderlands 2 share its left edge. All themes keep the eight-pixel bottom margin, in GUI units. The weapon works upwards from its baseline, and the ability row starts three scaled units below it. On narrow windows their union moves above the centered hotbar, offhand and status rows. Additional health, armor and absorption increase that reserve. At very short heights, the renderer reduces scale enough to fit an active weapon-perk banner above the stack. The settings preview uses the same weapon renderer and the same ability artwork as gameplay.

`CombatHudLayout` computes placement without touching the game state. `BinderHud` converts the owner-only synchronized Binder snapshot to four presentation slots. Slot indices correspond directly to the four casting key mappings, including empty slots. Duplicate ability bindings use the same ID-based deadline. HUD updates read local game time and the synchronized snapshot and generate no network traffic.

The layout arithmetic was checked over 5,760 combinations of GUI size, HUD scale, theme, offhand, active bindings and weapon state. Widths ranged from 280 to 1,920 GUI units, including exceptionally narrow configurations. The full graphical fixture separately exercises the shipped client and server.
